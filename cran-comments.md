## Submission

estimatr 2.1.0 is a feature release, the first since 2.0.1 on 2026-10-10. It adds arguments rather than changing defaults: `df_type` (the Bell and McCaffrey Satterthwaite degrees of freedom for HC2, and Welch's on a two-group design), `alternative` for one-sided tests in `difference_in_means()`, `horvitz_thompson()`, and `lh_robust()`, `first_stage` in `iv_robust()`, the clustered `se_type` values `"CR3"` and `"stata_nested"`, and ivreg's three-part instrumental-variables formula. It also adds the stats and sandwich methods that `lm_robust()`, `lm_lin()`, and `iv_robust()` fits lacked, so that `sandwich::vcovHC()`, `estfun()`, `bread()`, `hatvalues()`, `model.matrix()`, `terms()`, `lmtest::bptest()`, and `emmeans()` give the answer the equivalent `lm()` or `ivreg::ivreg()` fit gives, or refuse with a message naming what the fit does not store. `vignette("post-estimation-contract")` renders the file the tests check: 72 probes of stats and sandwich generics on eleven fits, each cell promising agreement with `lm()` or `ivreg()`, a refusal, or an error, and the page is built from the same file the tests read.

Four changes reach an existing call as a difference, and all four are deliberate. A weighted, unblocked `difference_in_means()` now has Welch degrees of freedom rather than n - 2, so it equals `lm_robust(y ~ z, se_type = "HC2", df_type = "welch")` in every number, as the unweighted one already did; its estimate and standard error are unchanged. A coefficient fitted exactly returns `NA` for its standard error under every clustered `se_type`, where CR0, `"stata"`, and weighted CR2 returned a number of order 1e-9 and unweighted CR2 and CR3 returned `NaN` with a warning blaming the design. `sandwich::bread()` on an estimatr fit no longer falls through to sandwich's default, which returned the robust variance times n (153.9 on `mpg ~ hp`, where `lm()` gives 5.72) with no warning, and `model.matrix()`, `model.frame()`, and `terms()` now describe the design the fit used, where `model.matrix()` errored and `terms()` on an `lm_lin()` fit described a design the fit had not used, so `lmtest::bptest()` tested the wrong model. An `lm_lin()` fit is now classed `c("lm_lin", "lm_robust")`; `inherits(fit, "lm_robust")` is unchanged. `NEWS.md` groups the entries as behaviour changes, new, and fixes, in that order.

This version was written by the maintainers working with AI assistance (Claude, from Anthropic), as 2.0.0 and 2.0.1 were. `vignette("estimatr2.0")` says so, and `vignette("mathematical-notes")` pairs each estimator's definition with a measurement of estimatr against that definition, to machine precision, computed when the vignette is built; the vignette ends in `stopifnot()`, so a broken identity fails the check rather than printing FALSE in a table. The evidence for this release: a suite of 8,639 assertions, 691 of them against answers recorded from an installed estimatr 1.0.6 and 844 against independent implementations (`sandwich`, `clubSandwich`, `ivreg`, Stata, `fixest`, `plm`, and `blkvar`), with the full returned surface of sixteen fit types pinned by test; and the post-estimation contract, 792 cells each run in a fresh R process. The contract runs where `NOT_CRAN` is set and skips on CRAN, since it starts 73 R processes and takes about two minutes.
